# Intro

最近 OpenAI 虽然送了很多重置，但是它的过度小心和防御性编程严重拖累了我的一些工作。

于是很想用 Claude Code，但我最主要面临的问题有如下这么几个：

  • 环境问题，需要特别配置网络等环境避免封号
  • 分发问题，有多台开发机，那么每一个开发机都要因为上面的环境问题而进行适配，会很麻烦
  • 使用体验问题，使用体验最好能接近当前最好的 Codex Desktop，如果能 cli2wewb 使得我随时用手机 / 笔记本等终端设备用浏览器打开使用就更好了
  • 模型能力问题，因为 Anthropric 和 OpenAI 在训练 Coding 模型的时候会针对自家 CLI 的接口进行调优优化，包括对源代码文件频繁的 View/Edit 等操作和执行 Shell 指令，如果号池机不能使用这些 CLI 原生功能，比如会降低模型的能力

可能你会觉得反代能轻松解决这些问题，但我首先否决反代，一方面是我已经反代了 Codex 很长一段时间，我已经遇到了降智问题，是观察得出的结果。另一方面从技术上讲，实际上开源社区里诸如 sub2api 和 CLIProxyAPI 这些反代工具是 “破绽百出” 的：

  • 首先不用官方 CLI 的首先就会因为官方远端只看得到推理请求看不到遥测数据而被发现了，更别提修改了 system prompt 的使用更是推理的时候就能发现。
  • 就算是使用官方 CLI 接反代，只要存在分发到不同环境，在远端官方看来就是同一个 CLI 发送了 2 种不同的遥测数据，同样能揪出来。
  • 严格限制一个号同时只能反代给一个环境用，也就是槽位分配限制，看上去没有上面两个问题了，但是官方 CLI 依然能上报当前使用 CLI 的方式和鉴权相关信息，必然会和反代系统里那个账号的授权信息不一样。
  • 那在此基础上反代系统逆向和伪装官方授权，将一模一样的授权 token 给到下游 CLI，下游 CLI 还修改本地 DNS 让官方域名指向反代网关使得 BASE_URL 也和官方一模一样？TLS 自签证书链必然会向 CLI 暴露中间人劫持的存在。

实际上，就好比完全逆向微信我们就能随便接 BOT 而不被封号，只要完全逆向官方 CLI，我们还真能在避免上述问题的前提下用反代。实际上这样的做法已经存在了，不过完全逆向以及持续跟进官方更新是成本极高的事情，我所见到的都是利用此道盈利的商业模式，例如 rawchat.cn 和 reclaude.ai 。他们完全逆向了官方 CLI，要求用户使用他们专门改良的二开 CLI，实现伪装所有遥测数据的上报。

# 拓扑与网络规划参数

网络拓扑上，采用双网桥隔离（双臂）+ LXC 网关 TUN + DNAT 端口映射的架构，能够实现号池机与外部主网的二层物理隔离。外部机器连接 LXC 网关的 IP 访问号池机的 SSH 与 Web 服务，而号池机发出的外网请求则 100% 强制进入家宽代理，不存在任何因配置重置或 ICMP 重定向导致的 IP 泄漏隐患。

本质上就是普通的家庭路由器透明代理，如果不使用 PVE，也可以通过普通路由器或其他软路由设备对你的真机号池机搭建。

这里我列出我的搭建过程各项参数，后续按照如下参数配置：

LXC 网关 eth1vmbr1 (内网桥)10.10.10.1/24留空号池专用内网的唯一网关出口

# PVE 宿主机网桥与网卡绑定

这里我的 PVE 版本为 9.1.9

创建 LXC 和 VM 过程略。

  1. 创建隔离内网桥 vmbr1 ：
    登录 PVE 网页管理端，依次进入 节点 →\rightarrow→ 系统 →\rightarrow→ 网络 →\rightarrow→ 创建 →\rightarrow→ Linux Bridge：
  • 名称： vmbr1
  • IPv4/CIDR、网关、桥接端口： 全部留空（使其成为纯粹的内部虚拟交换机）。
  • 点击右上角 应用配置 (Apply Configuration)。
  1. 创建 LXC 网关，同时配置双网卡：
    选中 LXC 容器 →\rightarrow→ 网络 (Network)：
  • eth0 ： 桥接 vmbr0 ，IPv4 设为 172.18.198.209/26 ，网关设为 172.18.198.254 。
  • 点击上方 添加 (Add) 新增 eth1 ：桥接 vmbr1 ，IPv4 设为 10.10.10.1/24 ，网关留空。
  1. 创建号池 KVM 虚拟机，同时绑定单网卡：

  • 将桥接配置为 vmbr1 。
